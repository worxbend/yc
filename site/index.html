▸ Terminal-native YouTube live chat

YouTube live chat that lives in your terminal.

$ yc chat --channel @terminalrenaissance Example command: yc chat --channel @terminalrenaissance

yc is a keyboard-first YouTube live chat client written in Go. The Data API gives you 10,000 units a day; polling at the cadence YouTube advises burns them in under three hours. yc meters every call, stretches its own interval to make the day last, and shows you the arithmetic on every frame.

Nothing to sign up for. Mock mode is the real UI against scripted chat.

The differentiator

Ten thousand units a day. yc makes them last.

Twitch gives you a socket. YouTube gives you a budget. Every design decision in yc falls out of that.

8,850 / 10,000 est · 12% left

STRETCHED is not a warning that yc is misbehaving — it means yc is deliberately polling slower than YouTube allows, so the day lasts. The mode label names why the loop is running at the cadence it is running at, every frame.

  • A reserve, held back by default (10%) — so sending and moderation still work after reading has stopped.
  • --session-hours N — tell yc how long you plan to stream and it spends the budget over exactly that window.
  • --follow-server-cadence — opt out of stretching and poll at the server's advised interval, budget be damned.
  • ctrl+r — override a quota-paused session and reconnect anyway.

Cadence calculator

Same arithmetic yc runs at startup. Every figure is an estimate.

2,000 est.polls the budget buys
43s est.interval that spans the session
10,000 est.units spent by the end

The honesty contract. Google publishes no unit cost for any live-chat method. Every figure on this page is community-observed and marked est. — yc's ledger is an estimate, not an invoice. The Google Cloud Console is the only authority on what you have actually spent. Details in docs/quota.md.

Why yc

Built for people who already live in a terminal

Every surface is keyboard-reachable, resize-aware, and designed to stay readable when chat is moving fast.

⟳

A quota meter in the status bar

The budget, the estimate, and the effective cadence on every frame — plus the projected exhaustion time and the reset boundary. You never have to guess how much day is left.

⏱

Budget-aware poll pacing

pollingIntervalMillis is an absolute floor yc never polls beneath; above it, the interval is whatever makes the day last. ±10% jitter, backoff on rateLimitExceeded, and a reserve so sends survive.

🔑

Two credential modes, both first class

An API key reads any public live chat with no OAuth at all; yc login runs a Google installed-app flow (loopback + PKCE) for sending. Missing capabilities disable controls with a reason instead of hiding them.

🎨

58 built-in themes

53 dark — including the house yc preset and 24 vibrant near-black palettes — and 5 light, plus a custom hex palette. ctrl+t previews live.

🧩

Three message layouts

inline for density, grouped for an author header with the run collapsed beneath, compact for text only. Swap at runtime with ctrl+g, or set message_layout to keep it.

@

@mention autocomplete

Completes from the people yc has actually seen speak — YouTube reports no presence, so there is no member list to fake. Prefix matches outrank substring matches; tab accepts.

◈

Every live-chat event, normalized

Super Chats, Super Stickers, gifts, memberships, milestones, gifting bursts, polls, bans, tombstones, members-only mode, chat ended — and an unknown snippet.type degrades into a readable row instead of a crash.

🔒

Secrets stay redacted

Access tokens, refresh tokens, client secrets, API keys, OAuth codes, state, PKCE verifiers, and authorization URLs are kept out of output, logs, errors, and diagnostics by design.

🧪

Mock mode, zero setup

The whole UI with no credentials, no network, and no quota. Good for trying yc, taking screenshots, or debugging your terminal before a stream starts.

🩺

Honest diagnostics

yc doctor runs 15 checks and reports what it verified and what it could not; yc quota prints today's estimated ledger without spending a unit.

Standing disclosure: nothing here has been validated against a real YouTube account. Every claim above is backed by tests, mock transports, and recorded fixtures — not by a live broadcast. What has actually been run, and what has not, is tracked in docs/manual-validation.md.

Install

Running in about thirty seconds

Try it with no credentials first — mock mode needs no Google project, no key, and no network.

01Try it — no credentials

# the full UI against scripted mock chat
$ go run ./cmd/yc chat --mock

02Install it

# downloads, verifies the checksum, installs to ~/.local/bin
$ curl --proto '=https' --tlsv1.2 -sSf \
    https://github.com/worxbend/yc/releases/latest/download/install.sh | bash
# arch is amd64 or arm64
$ base=https://github.com/worxbend/yc/releases/latest/download
$ curl -sSLO "$base/yc_linux_amd64"
$ curl -sSLO "$base/yc_linux_amd64.sha256"
$ sha256sum -c yc_linux_amd64.sha256
$ install -m 0755 yc_linux_amd64 ~/.local/bin/yc
# no Go toolchain needed on the host
$ docker build -t yc:local .
$ docker run --rm -it yc:local chat --mock
# Go 1.26 or newer
$ git clone https://github.com/worxbend/yc.git
$ cd yc
$ go build -o yc ./cmd/yc
$ ./yc chat --mock

Linux amd64 and arm64. There are no macOS or Windows builds — build from source, or use the container.

03Connect to real YouTube chat

Bring your own Google Cloud project. yc ships with no built-in application and no API key. Create a project, enable YouTube Data API v3, and give yc either an API key (read-only) or a Desktop OAuth client ID — walkthrough in docs/register-google-app.md.

The two credential modes and what each one can do
ModeCanCannot
API key Read any public live chat. No OAuth, no browser, no consent screen. Send, delete, time out, or ban.
OAuth Read, send, and moderate as the signed-in account. Nothing yc supports — but it needs a Desktop client and a consent screen. 
# read-only: any public live chat
$ export YC_YOUTUBE_API_KEY="<api key from Google Cloud>"
$ yc chat --video dQw4w9WgXcQ

# read + send: installed-app OAuth (loopback + PKCE)
$ export YC_GOOGLE_CLIENT_ID="<desktop-app client id>"
$ yc login
$ yc doctor
$ yc chat --channel @somechannel

yc login never prints or logs the access token, refresh token, authorization code, OAuth state, PKCE verifier, authorization URL, client secret, or API key. Every placeholder above is an obviously fake angle-bracket marker, and that is the same rule the code enforces on itself.

Keyboard

Everything is a keystroke away

Every binding comes from one table in internal/app/keymap.go, which also generates the footer, the help overlay, and the command palette. A coverage test fails when a handled ctrl key is missing from it.
